This marker signifies a link to external material. I use it primarily for projects to collect links to reference material (presentations, websites, and so on).

This marker has an `export-links` property, set to `true`. That makes any external links show up in the `links` query for the HTTP server. Try:

```zsh
curl -s http://localhost:7767/curators/demo/queries/links\?document\=Markdown%20Curator
```

It should output this:

<!--query:links 
document: "Markdown Curator"
_format: json
-->
```json
{"items":[{"name":"Jetty HTTP Server documentation","url":"https://jetty.org/docs/jetty/12.1/programming-guide/server/http.html"},{"name":"Alfred Markdown Curator workflow","url":"https://github.com/voostindie/alfred-markdown-curator-workflow"}]}
```
<!--/query (75f12e7d)-->

> Note that here the `links` query is used in the page, which is *exactly what you shouldn't do*, as this query is not built for automatic refreshing and rewriting when relevant things change. For the purpose of this example, it's okay.
> 
> Also note the "secret" `_format` property in the query definition above. It can be added to any query on any page to change the format into something other than Markdown. What the query supports depends on the vault, but typically `json` will work.

...provided that the server is enabled (`-s` or `--server`) and that it's running on its default port of 7767.

Do you have other markers that typically hold links to external content and that you want to include in the output of the `links` query? All you need to do is set the `export-links` property.

By the way: the `links` query also includes any links in the *Links* section of each document. That name can be overridden, but that needs to be done in the Java code of the [[Markdown Curator Demo]].

On my Mac the keyboard snippet `,ml` expands to this marker.
